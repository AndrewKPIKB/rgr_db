# РГР: застосунок бази даних PostgreSQL (сервіс знайомств)

Розрахунково-графічна робота з дисципліни «Бази даних та засоби управління» (КПІ ім. Ігоря Сікорського, КВ-41).

**Мета:** набути навичок розроблення консольного застосунку на Python 3, що взаємодіє з PostgreSQL засобами параметризованих SQL-запитів (Psycopg 3, без ORM), коректно обробляє помилки БД і має структуру за шаблоном MVC.

## Предметна область і база даних

Сервіс знайомств: користувач реєструється (email, телефон), має профіль (ім'я, дата народження, стать), налаштування пошуку (бажана стать, вікові межі) та ставить лайки іншим користувачам. БД з лабораторної роботи №1, схема `LABA_1_FINAL`.

| Таблиця | Призначення |
|---|---|
| `User` | користувач: email, хеш пароля, телефон, дата створення, `is_verified` (boolean) |
| `Profile` | профіль (зв'язок 1:1 з User) |
| `Preference` | налаштування пошуку (зв'язок 1:1 з User) |
| `Like` | лайк одного користувача іншому (User–User, M:N) |

Усі зовнішні ключі мають `ON DELETE CASCADE`: при вилученні користувача його профіль, налаштування та лайки вилучаються автоматично. Перед вилученням застосунок показує, скільки залежних записів буде вилучено, і просить підтвердження. Обмеження цілісності (PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK) визначені в `sql/schema.sql`.

## Структура проєкту

```
rgr_db/
├── main.py                       # точка входу
├── requirements.txt
├── .env.example                  # шаблон налаштувань підключення
├── sql/
│   ├── schema.sql                # схема, таблиці й обмеження
│   ├── migration_is_verified.sql # лише для БД, створеної до появи is_verified
│   ├── generate.sql              # генерація даних (N = 10)
│   ├── check_integrity.sql       # перевірка цілісності згенерованих даних
│   ├── search_examples.sql       # пошукові запити для EXPLAIN ANALYZE
│   ├── indexes.sql               # створення індексів
│   ├── drop_indexes.sql          # вилучення індексів
│   ├── truncate.sql              # очищення таблиць
│   ├── demo_restrict_on.sql      # демонстрація: перемкнути лайки на RESTRICT
│   └── demo_restrict_off.sql     # демонстрація: повернути CASCADE
├── model/                        # Model: усе, що працює з PostgreSQL
│   ├── db.py                     # підключення
│   ├── tables.py                 # опис таблиць і полів (CRUD)
│   ├── crud.py                   # SQL перегляду/внесення/зміни/вилучення
│   ├── generator.py              # SQL генерації даних
│   ├── search.py                 # параметризовані пошукові запити
│   └── errors.py                 # переклад помилок PostgreSQL
├── view/
│   └── console.py                # View: меню, введення, виведення (без SQL)
└── controller/                   # Controller: розбір введення, виклики Model
    ├── main_controller.py        # вибір пункту завдання
    ├── app.py                    # пункт 1 (CRUD)
    ├── generation_controller.py  # пункт 2 (генерація)
    ├── search_controller.py      # пункт 3 (пошук)
    └── inputs.py                 # спільний розбір введення
```

**MVC:** Model виконує SQL (значення передаються параметрами Psycopg, імена таблиць — через `psycopg.sql.Identifier`); View лише читає й виводить; Controller перетворює введення на типізовані значення, викликає Model і передає результат у View.

## Залежності

- Python 3.12
- PostgreSQL 13 або новіший (використовується `gen_random_uuid()`)
- Psycopg 3 (`psycopg[binary]`), python-dotenv (див. `requirements.txt`)
- pgAdmin 4 (для виконання SQL-скриптів)

## Налаштування та запуск

1. Створіть порожню базу даних `rgr_db` (pgAdmin: Databases → Create → Database).
2. У Query Tool цієї бази виконайте `sql/schema.sql` (створює схему `LABA_1_FINAL`, таблиці й обмеження).
3. Скопіюйте `.env.example` у `.env` і впишіть свій пароль PostgreSQL (файл `.env` не потрапляє в репозиторій).
4. Створіть середовище та встановіть залежності:

   ```
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
5. Запустіть застосунок:

   ```
   python main.py
   ```

## Меню

```
РГР: ОБЕРІТЬ ПУНКТ ЗАВДАННЯ
├── 1. Перегляд, внесення, редагування, вилучення (таблиці User, Profile, Preference, Like);
│        перед вилученням користувача показуються залежні записи й запитується підтвердження
├── 2. Генерація даних SQL-запитом: окрема таблиця або «Повний набір»; кількість вводить користувач
├── 3. Пошук: 1) за профілем (ILIKE, стать, діапазон дат, True/False);
│        2) найпопулярніші користувачі (GROUP BY, діапазон кількості лайків);
│        3) кандидати за налаштуваннями користувача;
│        4) за налаштуваннями (бажана стать, діапазони min_age та max_age)
└── 0. Вихід
```

Після кожного пошуку виводиться кількість рядків і час виконання в мілісекундах. Оператор `ILIKE` — регістронезалежний варіант `LIKE` у PostgreSQL.

## Відтворення перевірки швидкодії

1. Очистіть таблиці: `sql/truncate.sql`.
2. У застосунку: пункт 2 → «Повний набір» → `100000`.
3. Перевірте дані: `sql/check_integrity.sql` (усі порушення = 0); виконайте `ANALYZE;`.
4. Без індексів: `sql/drop_indexes.sql`, далі запити з `sql/search_examples.sql` під `EXPLAIN ANALYZE`.
5. З індексами: `sql/indexes.sql` і повторіть запити.

Приклад `user5@example.com` у запиті 3 існує, якщо генерацію виконано на порожній базі.

## Демонстрація RESTRICT / CASCADE

1. `sql/demo_restrict_on.sql` — зовнішні ключі лайків стають `RESTRICT`.
2. У застосунку (пункт 1 → Користувачі → Видалити) вилучіть користувача, який має лайки: застосунок покаже залежні записи й повідомлення про заборону.
3. `sql/demo_restrict_off.sql` — повертає `CASCADE`; повторне вилучення каскадно вилучає залежні записи.
